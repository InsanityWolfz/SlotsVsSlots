# Slots vs. Slots

An 8-bit roguelike where two slot machines fight. You don't aim, hold or nudge: the reels decide
each fight. Your choices come between fights: which enemy to take at a fork, which card to draft,
what to buy at the Cashier, which charms and relics to build around.

- **3 acts:** the House, the Mirror and (after a GREEN stake win) the Dealer.
- **5 starting slot machines,** each with its own hero.
- **Charms** go on a symbol on one reel. The same charm on all 3 reels is a full set.
- **Relics** are passive rules that last the run.
- **BONUS WHEEL and RELIC RUSH** vouchers can drop mid-fight. They pay out if you win the fight.
- **HIGH STAKES:** each slot machine has its own stake ladder. Win a full run at your best stake to
  unlock the next one.
- **Saves:** your unlocks, stakes, collection log and hiscores stay in your browser between
  sessions. There are no mid-run saves.

## Develop

```bash
npm install
npm run dev        # http://localhost:5173 (debug helpers + TUNE panel)
npm test           # rules, balance invariants, saves
npm run sim        # headless balance sim
npm run build      # typecheck + public build -> dist/
```

### Controls

| Key | Action |
|---|---|
| Space | Spin (manual mode) / skip the current animation |
| Click | Skip the current animation |
| A | Toggle auto-spin |
| 1 / 2 / 3 | 1× / 2× / 4× speed |
| R | New run (press twice mid-run) |
| M | Mute |
| L | Combat log |
| T or \` | Tuning panel (dev builds only) |

### Layout

```
src/core/     pure rules engine: deterministic, no DOM (fight, run, enemies, relics, stakes, profile)
src/sim/      headless simulator (npm run sim)
src/present/  presentation: game clock, camera juice, reels, machines, HUD, fx, director
src/render/   pixel art data (generated by tools/build-art.mjs), sprite cache, pixel font
src/audio/    procedural Web Audio synth
src/ui/       menus, run screens, tutorial callouts, combat log, tuning panel (dev)
tools/        art pipeline (build-art.mjs), balance harnesses (tools/balance), frame capture server
playtest/     playtest and QA reports from development
loop/STATE.md design constraints and the iteration log
```
